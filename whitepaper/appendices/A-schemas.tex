% Appendix A: Complete JSON Schemas
\chapter{Complete JSON Schemas}
\label{app:schemas}

This appendix provides complete JSON Schema definitions for all \tprotocol{} data structures, including core protocol types and network-specific payload formats.

\section{Core Protocol Schemas}

\subsection{PaymentRequired Schema}

The \code{PaymentRequired} structure is returned by servers in HTTP 402 responses, describing acceptable payment methods.

\begin{lstlisting}[language=json,caption={PaymentRequired JSON Schema}]
{
  "$schema": "https://json-schema.org/draft/2020-12/schema",
  "$id": "https://t402.io/schemas/payment-required.json",
  "title": "PaymentRequired",
  "description": "Server response indicating payment requirements",
  "type": "object",
  "required": ["t402Version", "resource", "accepts"],
  "properties": {
    "t402Version": {
      "type": "integer",
      "const": 2,
      "description": "Protocol version (must be 2)"
    },
    "error": {
      "type": "string",
      "description": "Human-readable error message"
    },
    "resource": {
      "$ref": "#/$defs/ResourceInfo"
    },
    "accepts": {
      "type": "array",
      "items": { "$ref": "#/$defs/PaymentRequirements" },
      "minItems": 1,
      "description": "Acceptable payment options"
    },
    "extensions": {
      "type": "object",
      "description": "Protocol extensions"
    }
  },
  "$defs": {
    "ResourceInfo": {
      "type": "object",
      "required": ["url"],
      "properties": {
        "url": {
          "type": "string",
          "format": "uri",
          "description": "Canonical URL of the resource"
        },
        "description": {
          "type": "string",
          "description": "Human-readable resource description"
        },
        "mimeType": {
          "type": "string",
          "description": "Expected response MIME type"
        }
      }
    },
    "PaymentRequirements": {
      "type": "object",
      "required": ["scheme", "network", "amount", "asset", "payTo", "maxTimeoutSeconds"],
      "properties": {
        "scheme": {
          "type": "string",
          "enum": ["exact", "upto"],
          "description": "Payment scheme identifier"
        },
        "network": {
          "type": "string",
          "pattern": "^[a-z0-9]+:[a-zA-Z0-9]+$",
          "description": "CAIP-2 network identifier"
        },
        "amount": {
          "type": "string",
          "pattern": "^[0-9]+$",
          "description": "Amount in smallest units (e.g., wei)"
        },
        "asset": {
          "type": "string",
          "description": "Token contract address"
        },
        "payTo": {
          "type": "string",
          "description": "Recipient address"
        },
        "maxTimeoutSeconds": {
          "type": "integer",
          "minimum": 60,
          "maximum": 3600,
          "description": "Maximum authorization validity"
        },
        "extra": {
          "type": "object",
          "description": "Network-specific parameters"
        }
      }
    }
  }
}
\end{lstlisting}

\section{Network-Specific Payload Schemas}

Each blockchain network has a unique payload format reflecting its signing mechanisms.

\subsection{EVM Payload (EIP-3009)}

\begin{lstlisting}[language=json,caption={EVM TransferWithAuthorization Payload}]
{
  "$schema": "https://json-schema.org/draft/2020-12/schema",
  "$id": "https://t402.io/schemas/evm-payload.json",
  "title": "EVMPayload",
  "description": "EIP-3009 TransferWithAuthorization payload",
  "type": "object",
  "required": ["from", "to", "value", "validAfter", "validBefore", "nonce", "signature"],
  "properties": {
    "from": {
      "type": "string",
      "pattern": "^0x[a-fA-F0-9]{40}$",
      "description": "Payer address"
    },
    "to": {
      "type": "string",
      "pattern": "^0x[a-fA-F0-9]{40}$",
      "description": "Recipient address"
    },
    "value": {
      "type": "string",
      "pattern": "^[0-9]+$",
      "description": "Amount in token smallest units"
    },
    "validAfter": {
      "type": "integer",
      "description": "Unix timestamp after which authorization is valid"
    },
    "validBefore": {
      "type": "integer",
      "description": "Unix timestamp before which authorization is valid"
    },
    "nonce": {
      "type": "string",
      "pattern": "^0x[a-fA-F0-9]{64}$",
      "description": "32-byte random nonce"
    },
    "signature": {
      "type": "string",
      "pattern": "^0x[a-fA-F0-9]{130}$",
      "description": "EIP-712 signature (65 bytes)"
    }
  }
}
\end{lstlisting}
