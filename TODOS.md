## P1 — Must resolve before Phase 2

### Facilitator Economics Design
- **What:** Design sustainable economic model for hosted facilitator (per-tx fee, monthly subscription, or protocol fund sponsorship)
- **Why:** Free tier with real merchant volume incurs gas costs across multiple chains with no revenue offset. Currently unfunded beyond initial wallet top-ups.
- **Pros:** Sustainable growth, funds ongoing gas costs, enables self-service onboarding
- **Cons:** Any fee model may deter early adoption in price-sensitive underbanked markets
- **Context:** Outside voice flagged this as structural gap. Current wallet balances are critically low (Base 0.0099, BNB 0.0056, ETH 0.0098). Phase 2 targets $1K+ monthly volume which requires funded wallets.
- **Effort:** M (human: ~2 weeks / CC: ~2 days)
- **Priority:** P1
- **Depends on:** Phase 1 adoption signal (how many developers, what chains they use)

## P2 — Track for later phases

### HTTP Middleware DRY Cleanup
- **What:** Extract ~550 lines of duplicated code across @t402/express, @t402/fastify, @t402/hono into shared utilities in @t402/core
- **Why:** checkIfBazaarNeeded(), SchemeRegistration, paymentMiddlewareFromConfig() are copy-pasted identically in all 3 framework packages. Changes require 3 edits.
- **Pros:** Single source of truth for middleware logic, easier to maintain, catches bugs in one place
- **Cons:** Refactoring existing working code introduces regression risk
- **Context:** Eng review identified 45% code duplication across HTTP packages. Key candidates: (1) Move checkIfBazaarNeeded + SchemeRegistration to @t402/core, (2) Extract shared middleware factory, (3) Create settlement handler abstraction per framework.
- **Effort:** M (human: ~2 weeks / CC: ~1 hour)
- **Priority:** P2
- **Depends on:** None — can be done independently of Phase 1

### Geolocation Chain Selection
- **What:** IP geolocation-based chain selection for @t402/quick middleware (TRON for SEA, TON for CIS, EVM for West)
- **Why:** Underbanked market wedge requires regional chain defaults matching local wallet preferences
- **Pros:** Automatic chain selection reduces merchant configuration burden
- **Cons:** Adds external dependency (MaxMind/ipapi.co), privacy surface (payer IP logging), unreliable for VPN users
- **Context:** Outside voice in eng review flagged as premature for Phase 1. VPN usage is disproportionately high in underbanked markets, making geo unreliable. Phase 1 defaults to EVM/Arbitrum. Revisit in Phase 2 after adoption signal.
- **Effort:** M (human: ~2 weeks / CC: ~3 days)
- **Priority:** P2
- **Depends on:** Phase 1 adoption signal (which chains developers actually use)
